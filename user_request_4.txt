# FUTUREFORGE — AI CAREER GUIDANCE ENGINE & VERIFIED CAREER KNOWLEDGE BASE

## 1. PROJECT CONTEXT

We are developing **FutureForge, an AI-Driven Career and Education Guidance Application**.

The goal is to help students and working professionals understand their career opportunities and receive personalized, reliable, and practical guidance based on their education, skills, interests, experience, and career goals.

Our application already contains existing modules and functionality. Your task is to improve the AI career guidance capabilities and implement a structured career knowledge base without breaking existing features.

### Existing Technology Stack

* Frontend: React and Tailwind CSS
* Backend: FastAPI
* Database: PostgreSQL
* AI: Existing Gemini API integration
* Existing authentication and application infrastructure

First, inspect the actual repository and identify the technologies, existing AI integrations, database schema, API endpoints, UI components, and career-related modules. Adapt your implementation to the actual codebase rather than assuming that every component exists exactly as described here.

**Do not rebuild the application from scratch. Do not replace working functionality unnecessarily.**

## 2. PRIMARY OBJECTIVE

Implement a reliable AI career guidance system that follows this workflow:

**UNDERSTAND → ANALYSE → VERIFY → RECOMMEND → GUIDE**

The AI must understand the user's complete profile, analyse all relevant inputs, compare them with available career information, and provide clear, personalized guidance.

The system must not invent user skills, qualifications, work experience, career requirements, certifications, salary figures, or learning resources.

If sufficient verified information is unavailable, the system must ask relevant questions or transparently explain that it cannot currently provide a reliable recommendation.

Accuracy and honesty are more important than generating an answer for every query.

### Natural-Language Input Handling

Users must be able to enter information naturally instead of being restricted to predefined dropdown options.

Examples:

* "I am working as a digital marketer and also have teaching experience."
* "I know Python, Excel, communication, and basic data analysis."
* "I want to move from accounting into data analytics."

1. Facts explicitly provided by the user.
2. Potentially transferable skills inferred from verified user information.
3. Skills requiring confirmation.
4. Skills the target career requires but the user has not demonstrated.
5. Information that is missing or unknown.

Never convert an assumption into a confirmed user skill.

If an important detail is missing, ask a concise follow-up question.

Avoid asking questions that the user has already answered.

## 4. AI CAREER RECOMMENDATION ENGINE

Create or improve a reusable career recommendation service that can support the existing student and working-professional modules.

### Recommendation Process

1. Understand the user's profile and objective.
2. Identify relevant career families.
3. Retrieve the appropriate career knowledge records.
4. Compare confirmed user information with documented career requirements.
5. Identify relevant transferable skills.
6. Determine missing information.
7. Assess whether the available evidence is sufficient.
8. Generate recommendations only when adequately supported.
9. Explain the reasons for each recommendation.
10. Provide actionable next steps.

### Recommendation Categories

Where appropriate, present:

**A. Closely Related Careers**
Careers that align with the user's existing qualifications, skills, or experience.

**B. Career Growth Opportunities**
Roles that represent potential progression within the user's current field.

**C. Career Transition Opportunities**
Alternative careers that may be achievable after developing additional skills or meeting relevant requirements.

Do not force all three categories to appear if the available information does not support them.

### Every Recommendation Must Explain

* Why the career is relevant.
* Which confirmed user skills or experiences are applicable.
* Which skills require confirmation.
* Which skills need development.
* What qualifications or prerequisites apply.
* What the user should do next.
* Which knowledge-base information supports the recommendation.

Recommendations must be specific to the user.

Do not return generic lists of unrelated careers merely to fill the results page.

### Match Scores

Do not assign identical placeholder percentages to every career.

If a match score is displayed, calculate it using a documented, consistent method based on relevant factors such as:

* Confirmed skill alignment.
* Relevant experience.
* Qualification requirements.
* Career goal alignment.
* Missing or unverified requirements.

Explain what the score means.

Do not describe a profile-match score as the probability of getting hired.

If the available profile is insufficient for a meaningful score, ask for more information or display an appropriate status instead of inventing a percentage.

## 6. CRITICAL FEATURE — MISSING CAREER DATA HANDLING

This feature is mandatory.

The application must distinguish between:

1. Career data available and sufficient.
2. Career data available but incomplete.
3. User profile insufficient.
4. Career data unavailable.
5. AI service unavailable.

These situations must not produce the same response.

### Case A: Sufficient Data Available

Retrieve relevant career information, analyse the user's profile, and provide a personalized recommendation with supporting explanations.

### Case B: Career Data Exists but Is Incomplete

Use only the information that is adequately supported.

Ask additional questions or clearly identify which parts of the guidance require further verification.

Do not fabricate missing details.

### Case C: User Information Is Insufficient

Ask targeted follow-up questions.

For example, if a user requests a transition into business development but their profile does not establish whether they have client-facing or sales experience, ask about those responsibilities before treating them as existing skills.

### Case D: Career Is Not Covered by the Knowledge Base

Do not generate an authoritative-looking career pathway from unsupported assumptions.

Collect only the additional details needed to understand the request.

Then show a transparent message such as:

"This career path is not currently covered by our verified guidance database. We have recorded the guidance request for review, subject to the application's consent and privacy controls. We cannot provide a reliable, detailed recommendation at this time."

If a genuine review mechanism has been implemented, explain that the request can be reviewed and updated later.

Do not promise that an administrator will upload the information shortly unless the system actually supports that workflow.

### Case E: AI Service Is Unavailable

If verified career data is available, provide appropriate rule-based guidance where possible.

If reliable guidance cannot be generated, explain that the service is temporarily unavailable and avoid inventing a response.

### Important

A career title existing in the database does not automatically mean sufficient information exists to recommend it.

Check whether the required career, skill, qualification, and pathway information is available before generating detailed guidance.
